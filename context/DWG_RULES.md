# Золотые правила обработки DWG через accoreconsole

> [!IMPORTANT]
> Нарушение любого из этих правил приводит к аварийному завершению скрипта, повреждению файла чертежа или вечному зависанию консоли AutoCAD (`accoreconsole.exe`).

---

### Правило 1: `ezdxf` не читает `.dwg`
Библиотека Python `ezdxf` работает **исключительно** с форматом `.dxf`. Для работы с `.dwg` всегда используется консольная утилита AutoCAD:
`C:\Program Files\Autodesk\AutoCAD 2026\accoreconsole.exe`.

### Правило 2: Кириллица в путях ломает `accoreconsole`
AutoCAD CLI некорректно обрабатывает аргументы командной строки с кириллическими символами (например, `G:\Мой диск\Workspace\`).
**Обязательный пайплайн:**
1. Скопировать исходный DWG в `C:\Temp\input.dwg` (путь только ASCII).
2. Выполнить обработку в `C:\Temp\`.
3. Скопировать результат обратно в рабочую папку.

### Правило 3: `(load "файл.lsp")` заблокирован политикой безопасности AutoCAD
При вызове `(load ...)` в `accoreconsole` срабатывает SECURELOAD / защита от недоверенных путей.
**Решение:** AutoLISP код пишется **прямо внутри файла сценария `.scr`** (inline), без разделения на внешний `.lsp`.

### Правило 4: Вывод `accoreconsole` — двухбайтовый UTF-16
Консоль AutoCAD выводит символы в UTF-16LE с нулевыми байтами между символами. При чтении вывода в PowerShell обязательно применять очистку:
```powershell
& $accore /i "C:\Temp\input.dwg" /s "C:\Temp\script.scr" 2>&1 |
    Out-String | ForEach-Object { $_ -replace [char]0,'' }
```

### Правило 5: Формат `SAVEAS` в SCR — без расширения
При сохранении через команду `_.SAVEAS` в скрипте `.scr` указывается версия (например, `2018`), затем путь **без расширения `.dwg`**:
```scr
_.SAVEAS
2018
C:\Temp\output
_.QUIT
_Y
```

### Правило 6: Русская локаль AutoCAD требует `_Y` при выходе
При завершении сессии через `_.QUIT` русская локаль запрашивает подтверждение сохранения изменений. Английский символ `Y` отвергается русской локалью и вызывает бесконечное ожидание (зависание процесса).
**Всегда передавать:** `_Y` (с нижним подчёркиванием).

### Правило 7: Файлы DXF строго БЕЗ UTF-8 BOM
Если записать `.dxf` с маркером последовательности байтов (UTF-8 with BOM), AutoCAD выдаст синтаксическую ошибку заголовка при открытии.
**Запись в PowerShell:**
```powershell
$noBom = [System.Text.UTF8Encoding]::new($false)
[System.IO.File]::WriteAllLines("C:\Temp\file.dxf", $lines, $noBom)
```

### Правило 8: Обязательное удаление целевого файла перед `_.SAVEAS`
Если файл `C:\Temp\output.dwg` уже существует, AutoCAD при выполнении `_.SAVEAS` выдаст интерактивный запрос:
*«Файл с этим именем уже существует. Заменить? <N>»*
В консольном режиме ответить на этот запрос невозможно, и процесс намертво зависает.
**Обязательное действие перед вызовом:**
```powershell
Remove-Item "C:\Temp\output.dwg" -Force -ErrorAction SilentlyContinue
```

### Правило 9: Не использовать `_.DXFIN` в SCR при открытии DXF через параметр `/i`
Если запускать утилиту как `accoreconsole.exe /i "C:\Temp\file.dxf"`, AutoCAD **уже загрузил все объекты чертежа**. Если внутри скрипта повторно вызвать `_.DXFIN`, чертёж продублируется сам в себя (удвоение всех линий, блоков и текстов).
Скрипт конвертации DXF -> DWG должен содержать только `_.SAVEAS` и `_.QUIT`.

### Правило 10: Таблицы `ACAD_TABLE` недоступны через COM в `accoreconsole`
В консольном режиме `accoreconsole` отсутствует интерфейс ActiveX/COM — вызовы `(vlax-ename->vla-object)` возвращают `nil`.
**Решение (Ветка E):** редактировать блоки ячеек таблицы напрямую в текстовом формате DXF. При открытии модифицированного DXF AutoCAD автоматически регенерирует внутренний блок `*T...` с новыми MTEXT и правильными координатами.

### Правило 11: Удаление динамических полей (код 344) перед записью в ячейку
Если ячейка таблицы содержала динамическую формулу (например, `СУММА`), в DXF перед значением присутствует строка `344` со ссылкой на `AcDbField`. При записи статического числа эту строку нужно удалить, иначе AutoCAD пересчитает формулу и перезапишет результат.

### Правило 12: Чистка фрагментированных шрифтов ГОСТ
Шрифты `CS_Gost2304.shx` и `Russia-GOST_Topo.shx` часто отсутствуют в Windows, приводя к искажениям. В скриптах выполняется автоматическая замена в `STYLE` на `isocpeur.ttf` (`ISOCPEUR`) и удаление битых тегов `\f...;` регулярным выражением:
`-replace '\\[fFWwCkK][^;]*;', '' -replace '[\{\}]', ''`.
